# V8.33 type-frontier probes

Start with [the findings](../../../Evidence/TypeFrontier_2026-09-30/REPORT.md), then [the case index](PROBE_INDEX.csv). Each `TFnnnn.KL` has a native compiler log under `Evidence/TypeFrontier_2026-09-30/compiler_logs/`; accepted cases have a matching `PC/V8.33/TypeFrontier/tfnnnn.pc`. The [manifest](../../../Evidence/TypeFrontier_2026-09-30/manifest.json) records source and PC SHA-256 hashes. [Native analysis](../../../Evidence/TypeFrontier_2026-09-30/native_analysis.json) contains record spans and the bounded original-PC context comparison.

The 85 cases cover built-in scalar, vector, position, FILE/PATH/vision types; user aliases and alias chains; nominal structures with nested, array, string, BYTE/SHORT and position fields; one- and two-dimensional arrays, nested array aliases, variable-sized arrays, structure arrays; formals, member reads/writes and type-incompatibility controls. Six cases deliberately try class, interface, inheritance, implementation, and parameterized/generic spellings that are absent from the documented KAREL declaration grammar. A rejected spelling establishes rejection of that spelling by this compiler, not the impossibility of every conceivable dialect extension.

Builds used KTRANS V8.33 Build 25 and an isolated scratch `robot.ini`; the installed FANUC tree was read-only. To reproduce, use [the Samples compiler guide](../../../../COMPILING_KAREL_SAMPLES.md) and the archived [source-generation script](../../../Evidence/TypeFrontier_2026-09-30/scripts/build_type_frontier_probes.py). Do not infer the source type of an original-PC 2C cell from a matching allocation width or a routine name.
